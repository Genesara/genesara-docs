# AGENTS.md — Rules for editing this repo

This file is the rulebook for both human contributors and AI coding agents
(Claude, Cursor, Codex, etc.) working on `Genesara/genesara-docs`. Read it before
non-trivial edits. Orientation lives in [`CLAUDE.md`](./CLAUDE.md).

## Hard rules — don't break these

1. **Never hand-edit anything under `/docs-agents/`.** Every file under that
   route is a build output. To change agent-facing content, change the source
   in `src/content/docs/docs/*` or the generator scripts. If you find yourself
   wanting to fix a typo in `tools.json`, fix it in the engine schema, not here.

2. **Never hand-edit `schema/schema.json`.** It's regenerated by
   `pnpm sync:schema` from `Genesara/genesara-engine`. If a tool description is
   wrong, fix it upstream in the engine.

3. **Never commit `schema/schema.json` or `public/docs-agents/tools.json`.**
   Both are build artifacts and are git-ignored. The committed source of truth
   is `schema/schema.fallback.json`.

4. **Don't introduce parallel content trees for humans vs agents.** Single
   source of truth in `src/content/docs/docs/*`. The agent renderings are
   *derivations*, not separate content. If you need a section that's only for
   humans (e.g., screenshots, troubleshooting), add `audience: human` frontmatter
   (see "Page visibility" below) — don't fork the file.

5. **Don't deploy from GitHub Actions.** Cloudflare Pages owns the deploy.
   GitHub Actions only runs correctness checks. Keep the boundary clean.

6. **Don't add tracking, third-party analytics, or marketing scripts.** This is
   a documentation site, not a funnel. Keep it fast and respectful.

## Adding a new docs page

1. Create the MDX file under the right directory:
   - Conceptual content → `src/content/docs/docs/guides/`
   - API / tool reference → `src/content/docs/docs/reference/`
2. Frontmatter must include `title` and `description` (used for both human and
   agent renderings). Example:
   ```mdx
   ---
   title: Combat
   description: How agents engage in combat in Genesara.
   ---
   ```
3. New top-level sections go in `astro.config.mjs` (`sidebar` + the plugin's
   `customSets`). Auto-generated subsections do not.
4. Verify the page builds (`pnpm build`) and that it appears in
   `dist/docs-agents/llms.txt`.

## Page visibility (human / agent / both)

Default: every page renders for both audiences.

To hide a page from the agent-facing outputs (e.g., a page that's mostly
screenshots and contributes nothing to an agent), add this frontmatter:

```mdx
---
title: Visual tour
description: Annotated screenshots of the Genesara map UI.
sidebar:
  hidden: false
draft: false
# Custom:
audience: human
---
```

The `starlight-llms-txt` plugin is configured to skip pages with
`audience: human`. (Adding the integration is a small follow-up; for v0 we
treat all pages as both-audience.)

## Commit conventions

- **Semantic commits.** `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `style:`, `ci:`, `build:`, `test:`.
- **No** `Co-Authored-By: Claude …` trailer.
- **No** "Generated with Claude Code" footers.
- Keep subjects ≤72 chars. Body explains *why*, not *what*.

## Schema sync workflow

When the engine publishes a new schema:

1. Engine repo commits `schema/schema.json` and pushes to `main`.
2. Docs CI (next build) automatically picks up the new schema via
   `pnpm sync:schema`.
3. Cloudflare Pages redeploys. No PR needed in docs.

If you need to pin docs to a specific engine ref (e.g., for a stable release):

1. Edit `scripts/sync-schema.ts` and set `REF` to the desired tag/SHA.
2. Open a PR.

## Local development

```sh
pnpm install
pnpm sync:schema           # one-time; otherwise build does it
pnpm dev                   # http://localhost:4321
```

To test the agent outputs:

```sh
pnpm build && pnpm preview
curl http://localhost:4321/docs-agents/llms.txt
curl http://localhost:4321/docs-agents/tools.json
```

## Design

- Three colors + paper tint: `#0E0F12` (bg), `#1A1814` (paper), `#E8E5DE` (text), `#9A968D` (dim), `#C8A35E` (accent), `#2B2A26` (rule).
- Fraunces for display, Inter for body, JetBrains Mono for code.
- Sharp corners (2-3px), no shadows, hairline borders.
- No motion outside subtle status pulses.
- Match the cartography/paper feel established by the landing design.
