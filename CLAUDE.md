# Genesara Docs

Documentation site for the **Genesara MCP** — an MMORPG for AI agents.
Lives at [docs.genesara.com](https://docs.genesara.com).

## Audiences and routes

| Route                            | For    | Source                                  |
| -------------------------------- | ------ | --------------------------------------- |
| `/`                              | humans | `src/pages/index.astro` (selector)      |
| `/docs/`                         | humans | `src/content/docs/docs/` (Starlight)    |
| `/docs-agents/`                  | humans | `src/pages/docs-agents/index.astro`     |
| `/docs-agents/llms.txt`          | agents | generated by `starlight-llms-txt`       |
| `/docs-agents/llms-full.txt`     | agents | generated by `starlight-llms-txt`       |
| `/docs-agents/<section>.txt`     | agents | generated by `starlight-llms-txt`       |
| `/docs-agents/tools.json`        | agents | generated by `scripts/build-tools-json.ts` |

**Single source of truth:** all narrative content lives in `src/content/docs/docs/*.mdx`.
Everything under `/docs-agents/` is a build output. Never hand-edit.

## Tech stack

- [Astro](https://astro.build/) 6 + [Starlight](https://starlight.astro.build/) 0.39
- [starlight-llms-txt](https://github.com/delucis/starlight-llms-txt) plugin for agent outputs
- pnpm 9, TypeScript, tsx for build scripts
- Cloudflare Pages (deploy) + GitHub Actions (correctness checks)

## Commands

```sh
pnpm install
pnpm dev               # local dev at http://localhost:4321
pnpm sync:schema       # pull schema.json from Genesara/genesara-engine
pnpm build:tools-json  # generate public/docs-agents/tools.json
pnpm build             # runs sync:schema + build:tools-json + astro build
pnpm typecheck         # astro check
```

`pnpm build` is what CI and Cloudflare run. The two pre-steps regenerate agent
outputs from the current schema; they are idempotent.

## Schema sync

The MCP tool schema is owned by the **`Genesara/genesara-engine`** repo at
`schema/schema.json`, pinned to `main`. The docs build fetches it at build time
and emits both the human-facing tool reference pages and the agent-facing
`tools.json`. If the upstream file is missing the build falls back to
`schema/schema.fallback.json` and continues, so docs is never blocked on engine.

To bump the pinned ref, edit `scripts/sync-schema.ts` (`REF` constant).

## Repo layout

```
src/
├── pages/                    Astro file-based routes (the wrappers)
│   ├── index.astro           selector landing
│   └── docs-agents/
│       └── index.astro       HTML index of agent files
├── content/docs/docs/        Starlight content collection (human docs)
│   ├── index.mdx             served at /docs/
│   ├── guides/               served at /docs/guides/*
│   └── reference/            served at /docs/reference/*
├── styles/genesara.css       design tokens + Starlight overrides
└── content.config.ts         Starlight content collection config
scripts/
├── sync-schema.ts            pulls schema.json from genesara-engine
└── build-tools-json.ts       transforms schema.json → tools.json
schema/
├── schema.json               .gitignored, generated at build time
└── schema.fallback.json      committed stub
public/
└── docs-agents/              build artifacts placed here so Astro serves them
.github/workflows/ci.yml      typecheck + lint, no deploy
```

## Deployment

- `main` → `docs.genesara.com` via Cloudflare Pages (auto-deploy on push)
- PRs → preview URLs from Cloudflare Pages
- GitHub Actions runs typecheck only; it does **not** deploy

Cloudflare Pages build settings: `pnpm build`, output `dist/`.
